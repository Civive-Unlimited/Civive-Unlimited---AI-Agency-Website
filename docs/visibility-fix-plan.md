# Visibility Fix Plan

## Current framework

- Vite + React 19 SPA using `wouter` routes.
- SSR/prerender pipeline: `pnpm run build` builds client, builds `client/src/entry-server.tsx`, then runs `scripts/prerender.mjs`.
- SEO output is prerendered into `dist/public`; source crawl files live in `client/public`, and build-time crawl files are regenerated by `scripts/prerender.mjs`.

## Main files to edit

- `client/src/content/seo.ts`
- `client/src/content/site.ts`
- `client/src/content/topical-map.ts`
- `client/src/prerender-routes.ts`
- `client/src/App.tsx`
- `scripts/prerender.mjs`
- `client/src/components/Footer.tsx`
- homepage sections under `client/src/components/sections/`
- new route pages under `client/src/pages/`
- `client/index.html`

## Current SEO gaps found

- NAP has phone/email/domain but not the full GBP street address.
- Schema combines `Organization` and `ProfessionalService` but lacks full postal address, founder, localized `areaServed`, `priceRange`, and homepage-specific Organization/LocalBusiness clarity.
- Service schema exists only per route; core service list is not represented as distinct Service entities.
- Requested service pages and `/service-areas/springfield-mo` do not exist yet.
- Homepage FAQ does not match the requested visible FAQ set.
- Sitemap/prerender route list does not include the requested new service and local pages.

## Exact implementation plan

1. Add canonical business facts and local service area data to `seo.ts`.
2. Add service-page and Springfield landing-page content in `site.ts`.
3. Create reusable `ServicePage` plus `/service-areas/springfield-mo`.
4. Wire new routes in `App.tsx`, `prerender-routes.ts`, and topical map.
5. Upgrade prerender JSON-LD for Organization, LocalBusiness, and core Service graph entries.
6. Add compact homepage/footer areas-served links and standardize visible NAP.
7. Update homepage FAQ content and metadata.
8. Run type/build/SEO checks and write `docs/visibility-fix-report.md`.
